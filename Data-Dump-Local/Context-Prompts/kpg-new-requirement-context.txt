# NEW FRAMEWORK: Customer State Graph
Initially we want to augment the context during the negotiations phase using a Customer State Graph.

We want to use this Customer State Graph as context for future calls to make the conversation more personalized and effective.

We want this to be a personalized context that captures customer preferences, intents, nuances over multiple calls.

We want to also update this Customer State Graph after every call based on various analysis.
Notice that each customer may have multiple calls over time. We should be able to maintain previous conversations as separate nodes with it's own attributes and chain them chronologically. And we should be updating the Customer State Graph after every call. Each customer can be thought of a separate node. We can think of each customer having an isolate sub-graph within the larger Customer State Graph.

The Customer State Graph should be a super-set of disposition analysis, more generic, capturing details about customer preferences and other nuances.

Input data to the framework: (Initial)
Customer specific configuration file that contains customer profile and other relevant data and a single call transcript.
Graph to be updated after every call.
