## Node Types & Properties

### 1. Customer Node
Properties:
// Identity
- uuid: String (primary key)
- name: String
- phone: String
- alternate_numbers: List[String]

// Loan Context
- loan_number: String
- product_name: String (Two-Wheeler Loan, Personal Loan, etc.)
- emi_amount: Float
- total_payable_amount: Float
- pending_emi: Integer
- due_date: DateTime

// Financial Details
- bounce_accrued: Float
- penal_accrued: Float
- others_accrued: Float
- total_accrued: Float
- current_month_charges: Float

// Profile
- language_preference: String (HINDI/ENGLISH/etc.)
- customer_gender: String (male/female)
- customer_state: String

// Engagement Patterns
- total_calls: Integer
- successful_authentications: Integer
- wrong_number_reports: Integer
- callback_requests: Integer

// Status Flags
- is_disputed: Boolean
- is_problematic: Boolean
- is_deceased: Boolean
- is_high_risk: Boolean

// Metadata
- first_call_date: DateTime
- last_call_date: DateTime
- last_disposition_code: String
- created_at: DateTime
- updated_at: DateTime

### 2. Conversation Node
Properties:
// Identity
- uuid: String (primary key)
- name: String (Conversation #{call_sequence})
- call_sequence: Integer
- call_date: DateTime
- call_duration: Integer (seconds)

// Call Flow
- authenticated: Boolean
- nodes_traversed: List[String] (authenticate, negotiate, oncall_payment)
- final_node: String

// Behavioral Indicators
- customer_tone: String (Cooperative/Frustrated/Defensive/Neutral/Aggressive)
- objection_raised: String (charge_dispute/financial_hardship/technical/already_paid/none)
- payment_discussed: String (UPI/Card/Cash/None)
- language_barrier_encountered: Boolean

// Outcome Signals
- payment_attempted: Boolean
- payment_successful: Boolean
- ptp_given: Boolean
- callback_requested: Boolean
- escalated: Boolean
- terminated_early: Boolean

// Technical Details
- payment_link_sent_count: Integer
- transcript_snippet: String (key excerpts for quick reference)

// Metadata
- created_at: DateTime

### 3. Disposition Node
**Unified structure accommodating L1 + L2 disposition attributes**

Properties:
// L1 Classification (Core)
- uuid: String (primary key)
- code: String (ONP/PTP/FPTP/RTP/DIR/CPD/CDE/WNR/LMS/CBK/LBR/CHP/PPC/LDD/OTH/TP)
- name: String (human-readable disposition name)
- category: String (payment_success/payment_promise/payment_issue/customer_issue/call_issue/other)

// L2 Sub-Classification
- subdisposition: String (disposition-specific sub-category)
- subdisposition_details: String (reasoning behind subdisposition)

// Common Payment Fields (applicable to PTP/FPTP/TP/ONP)
- promised_payment_date: DateTime (null if not applicable)
- promised_payment_time: String (null if not applicable)
- exact_promised_amount: Float (null if not applicable)
- payment_mode: String (Branch/Field_agent/Novopay/Online/UPI/Card/etc.)

// Promise Quality Indicators (PTP/FPTP/TP)
- reason_for_delay: String (customer's stated reason)
- commitment_strength_score: Integer (1-5 scale, null if not applicable)
- ptp_honored: Boolean (null initially, updated on follow-up)

// Payment-Specific Fields
- claimed_payment_date: DateTime (CPD: when customer claims they paid)
- claimed_payment_time: String (CPD)
- transaction_id: String (CPD/ONP: receipt/order ID)
- amount_paid: Float (CPD/ONP)
- agent_verification_status: String (CPD: verified/unverified/pending)

// Technical/Payment Issues (LDD/ONP)
- failure_type: String (auto_debit/UPI/timeout/link_issue/cheque_bounce/etc.)
- error_details: String (specific error message or description)
- payment_status: String (ONP: initiated/completed/failed/dropped)

// Customer Contact Issues
- stage_of_hang_up: String (CHP: start/middle/voicemail)
- who_hung_up: String (CHP: Agent/Customer)
- customer_last_statement: String (CHP)

- receiver_name_relation: String (WNR/LMS: who answered)
- duration_had_number: Integer (WNR: days using this number)
- customer_availability_info: String (LMS)
- message_left_summary: String (LMS)
- alternate_contact_provided: String (LMS: name/number)

// Callback Details (CBK)
- callback_date: DateTime
- callback_time: String
- callback_reason: String (busy_driving/network_issue/busy_activity/payment_details/future_payment/other)
- alternate_callback_number: String

// Language Barrier (LBR)
- original_call_language: String (ISO 639-1 code)
- customer_preferred_language: String (ISO 639-1 code)
- language_barrier_phrase: String (specific transcript phrase)

// Dispute Details (DIR)
- dispute_type: String (card_not_taken/fraud/loan_not_availed/wrong_commitment/other)
- dispute_evidence: String (specific transcript phrases)

// Refusal Details (RTP)
- refusal_reason: String (dealer_dispute/medical/financial_emergency/no_capacity/out_of_town/other)
- refusal_evidence: String (specific transcript phrases)
- conditions_for_future_payment: String
- customer_alternative_proposal: String

// Deceased Customer (CDE)
- deceased_customer_name: String
- informant_name_relation: String
- date_of_expiry: DateTime
- cause_of_expiry: String
- guidance_provided: String (e.g., submit death certificate)

// Problematic Behavior (PPC)
- behavior_type: String (rude_abusive/doubtful_intent/general_problematic)
- behavior_details: String (specific examples/quotes)
- point_of_escalation: String (when in call it occurred)
- customer_emotional_state: String

// Other Classification (OTH/LDD)
- unclassified_reason: String (why it doesn't fit other categories)
- key_information_points: String (important unclassified details)

// Intent & Next Steps
- customer_intent: String (derived from intent mapping config)
- agent_guidance_provided: String (what agent advised)
- next_action: String (what should happen next)
- escalation_required: Boolean
- follow_up_required: Boolean

// Reasoning & Evidence
- classification_reasoning: String (why this disposition was chosen)
- supporting_transcript_quotes: String (key phrases from transcript)

// Metadata
- classified_at: DateTime
- classification_confidence: String (High/Medium/Low)

// Metadata
- classified_at: DateTime
- classification_confidence: String (High/Medium/Low)

### 4. Insight Node
Properties:
// Core
- uuid: String (primary key)
- type: String (payment_behavior/objection_pattern/negotiation_response/communication_style/financial_hardship/technical_comfort)
- text: String (the actual insight in English)
- category: String (behavioral/financial/communication/technical)

// Evidence
- from_calls: List[String] (conversation UUIDs)
- supporting_dispositions: List[String] (disposition codes from those calls)
- count: Integer (times observed across calls)
- first_observed: DateTime
- last_observed: DateTime

// Status
- active: Boolean
- expired: Boolean
- replaced_by: String (insight UUID if superseded)
- expiry_reason: String (contradicted/outdated/merged)

// Relevance
- confidence: String (High/Medium/Low)
- priority: String (High/Medium/Low - for negotiation strategy)
- impact_score: Float (0-1: how much this affects payment likelihood)

// Actionable Intelligence
- recommended_strategy: String (how to use this insight in next call)
- avoid_actions: String (what not to do based on this insight)

// Metadata
- created_at: DateTime
- updated_at: DateTime

## Edge Types & Properties

### 1. Customer --[HAS]--> Conversation
Properties:
- created_at: DateTime
- call_initiated_by: String (system/manual/callback)

### 2. Conversation --[NEXT]--> Conversation
Properties:
- days_between_calls: Integer
- disposition_changed: Boolean (did disposition category change?)
- escalation_progression: String (normal/escalated/de-escalated)

### 3. Conversation --[LEADS_TO]--> Disposition
Properties:
- classification_method: String (automated/manual/hybrid)
- reviewed_by: String (agent ID if manually reviewed)

### 4. Customer --[RELEVANT]--> Insight
Properties:
- relevance_score: Float (0-1)
- last_validated: DateTime
- validation_call_id: String (most recent call UUID validating this)

### 5. Insight --[DERIVED_FROM]--> Conversation
Properties:
- extraction_confidence: Float (0-1)
- key_evidence: String (specific part of conversation)

### 6. Insight --[CONTRADICTS]--> Insight (optional)
Properties:
- contradiction_reason: String
- resolution: String (which insight took precedence)

**payment_success**: ONP (with subdisposition: completed), CPD (if verified)
**payment_promise**: PTP, FPTP, TP
**payment_issue**: LDD, ONP (with subdisposition: failed/dropped)
**dispute**: DIR
**refusal**: RTP
**customer_issue**: CDE, PPC
**contact_issue**: WNR, LMS, CBK, CHP, LBR
**other**: OTH

## L2 Attribute Population Guidelines

**All dispositions populate:**
- code, name, subdisposition, subdisposition_details
- customer_intent (from intent mapping)
- classification_reasoning, supporting_transcript_quotes

**Disposition-specific required fields:**

**CHP**: stage_of_hang_up, who_hung_up, customer_last_statement

**WNR**: receiver_name_relation, duration_had_number

**CDE**: deceased_customer_name, informant_name_relation, date_of_expiry, guidance_provided

**LMS**: receiver_name_relation, message_left_summary, customer_availability_info

**CBK**: callback_date, callback_time, callback_reason

**LBR**: original_call_language, customer_preferred_language, language_barrier_phrase

**DIR**: dispute_type, dispute_evidence

**RTP**: refusal_reason, refusal_evidence

**CPD**: claimed_payment_date, amount_paid, transaction_id, agent_verification_status

**ONP**: payment_mode, payment_status, (if failed: error_details)

**PTP/FPTP/TP**: promised_payment_date, exact_promised_amount, reason_for_delay, commitment_strength_score, payment_mode

**LDD**: failure_type, error_details

**PPC**: behavior_type, behavior_details, customer_emotional_state

**OTH**: unclassified_reason, key_information_points

## Workflow: Adding a New Call

### Step 1: Load Customer
```
- Query Customer node by phone/uuid
- If not exists, create new Customer node from config
```

### Step 2: Create Conversation Node
```
- Generate uuid
- Set call_sequence = customer.total_calls + 1
- Extract conversation properties from transcript
- Create edge: Customer --[HAS]--> Conversation
```

### Step 3: Analyze & Create Disposition
```
- Run L1 classification (get disposition code)
- Run L2 extraction (get disposition-specific attributes)
- Map to intent using FINAL_INTENT_MAP_CONFIG
- Populate all relevant Disposition properties
- Create edge: Conversation --[LEADS_TO]--> Disposition
```

### Step 4: Link to Previous Conversation (if exists)
```
- Query previous Conversation (call_sequence - 1)
- If exists, create edge: PreviousConversation --[NEXT]--> CurrentConversation
```

### Step 5: Extract/Update Insights
```
For each potential insight from current call:
  - Check if similar insight exists (semantic similarity)
  
  Case A: New Insight
    - Create new Insight node
    - Create edge: Customer --[RELEVANT]--> Insight
    - Create edge: Insight --[DERIVED_FROM]--> Conversation
  
  Case B: Reinforces Existing Insight
    - Update existing Insight:
      * Append to from_calls list
      * Increment count
      * Update last_observed
      * Increase confidence if applicable
    - Create edge: Insight --[DERIVED_FROM]--> Conversation
  
  Case C: Contradicts Existing Insight
    - Update old Insight: set expired=True, expiry_reason="contradicted"
    - Create new Insight with updated information
    - Create edge: NewInsight --[CONTRADICTS]--> OldInsight
    - Create edge: Customer --[RELEVANT]--> NewInsight
```

### Step 6: Update Customer Node
```
- Increment total_calls
- Update last_call_date
- Update last_disposition_code
- Update status flags based on disposition:
  * DIR → set is_disputed = True
  * PPC → set is_problematic = True
  * CDE → set is_deceased = True
  * Multiple RTP → set is_high_risk = True
- Update engagement patterns (callback_requests, etc.)
```

## Query Patterns for Context Retrieval

### Get Customer State for Next Call
```cypher
MATCH (c:Customer {uuid: $customer_uuid})
OPTIONAL MATCH (c)-[:HAS]->(conv:Conversation)-[:LEADS_TO]->(d:Disposition)
WHERE conv.call_sequence = (
  SELECT MAX(conv2.call_sequence) 
  FROM (c)-[:HAS]->(conv2:Conversation)
)
OPTIONAL MATCH (c)-[:RELEVANT]->(i:Insight {active: true})
RETURN c, conv, d, COLLECT(i) as insights
ORDER BY i.priority DESC, i.confidence DESC
```

### Get Conversation History with Dispositions
```cypher
MATCH (c:Customer {uuid: $customer_uuid})-[:HAS]->(conv:Conversation)
OPTIONAL MATCH (conv)-[:LEADS_TO]->(d:Disposition)
OPTIONAL MATCH (prev:Conversation)-[:NEXT]->(conv)
RETURN conv, d, prev
ORDER BY conv.call_sequence ASC
LIMIT 5  // Last 5 conversations
```

### Get Active Insights by Priority
```cypher
MATCH (c:Customer {uuid: $customer_uuid})-[r:RELEVANT]->(i:Insight {active: true})
RETURN i, r.relevance_score
ORDER BY i.priority DESC, i.confidence DESC, i.impact_score DESC
LIMIT 10
```

### Get Payment Pattern Analysis
```cypher
MATCH (c:Customer {uuid: $customer_uuid})-[:HAS]->(conv:Conversation)-[:LEADS_TO]->(d:Disposition)
WHERE d.category IN ['payment_success', 'payment_promise']
RETURN d.code, d.subdisposition, d.promised_payment_date, d.ptp_honored, conv.call_date
ORDER BY conv.call_date DESC
```

### Detect Behavioral Trends
```cypher
MATCH (c:Customer {uuid: $customer_uuid})-[:HAS]->(conv:Conversation)
WITH c, COLLECT(conv.customer_tone) as tones, 
     COUNT(CASE WHEN conv.escalated THEN 1 END) as escalation_count,
     COUNT(CASE WHEN conv.callback_requested THEN 1 END) as callback_count
RETURN c.uuid, tones, escalation_count, callback_count
```

## Implementation Notes

1. **Schema Flexibility**: All disposition-specific fields are nullable, allowing the schema to accommodate any disposition type without creating separate node types.

2. **L2 Integration**: The schema directly maps to L2 disposition extraction fields, making it straightforward to populate from the LLM extraction output.

3. **Queryability**: Core fields remain at top level for efficient querying, while disposition-specific details are organized by functional groups.

4. **Temporal Tracking**: DateTime fields throughout enable trend analysis and pattern detection over time.

5. **Intent Mapping**: The `customer_intent` field stores the mapped intent from `FINAL_INTENT_MAP_CONFIG_COLLECTIONS`, enabling consistent strategy application.

6. **Evidence Trail**: `supporting_transcript_quotes` and `classification_reasoning` maintain explainability for all classifications.

7. **Insight Evolution**: The Insight node structure supports dynamic updates, expiration, and contradiction handling as customer behavior evolves.
